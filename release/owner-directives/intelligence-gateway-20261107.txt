## 1. Fundamental architecture

Implement a versioned Unified Intelligence Gateway accessible to Codex through supported MCP tools or an equivalent explicitly configured client interface.

The gateway must expose existing Unified capabilities without replacing their owners.

- Grid owns market data collection and source provenance.
- Storage owns datasets, manifests, integrity and publication.
- Strattester owns strategy testing and existing paper ledger.
- Math owns numerical and statistical computation.
- MetaAnalyse owns its existing analytical capabilities.
- Terminan owns visualization.
- Unified owns scheduling, authority, control and release coordination.
- Node Supervisor owns authorized local lifecycle operations.

Codex is an intelligent client and development assistant, not a new consensus authority, exchange executor or critical always-on service.

## 4. Data Exploration API

Support server-side selection by:

- Exchange.
- Market category.
- Instrument identity.
- Dataset version.
- Time range.
- Event type.
- Aggregation.
- Data quality.
- Provenance.
- Research capability.

Support candles, public trades, order book snapshots/deltas, funding and derived features only where the source actually provides them.

Every response must include:

- Schema version.
- Dataset identity.
- Instrument identity.
- Time semantics.
- Units.
- Coverage.
- Gap indicators.
- Source/content digests.
- Integrity status.
- Capability limitations.

Never fabricate unavailable market history.

Use bounded pagination, server-side aggregation and immutable artifact references.

Do not return unlimited tick streams or database credentials to Codex.

## 5. Scientific Research API

A research request should define:

- Research hypothesis.
- Strategy version.
- Dataset manifest.
- Simulation fidelity.
- Input capabilities.
- Training/validation/test periods.
- Execution model.
- Fee/slippage/funding assumptions.
- Numerical configuration.
- Resource budget.
- Deterministic seed where applicable.
- Expected outputs.

Use existing Math, Strattester and MetaAnalyse components.

Preserve historical causality.

Prevent look-ahead bias, data leakage and double subtraction of trading costs.

Separate exploratory results from independently validated results.

A high historical win rate must never automatically authorize paper activation.

## 8. Observer Agents

Implement bounded, deterministic observers:

**Data Quality Observer**
- Gaps, stale book, invalid sequences, source freshness.

**Research Observer**
- Job failures, statistical warnings, experiment reproducibility.

**Strategy Observer**
- Paper performance degradation, drift and risk threshold breaches.

**Infrastructure Observer**
- Node health, storage, queues, authority, release compatibility.

**CI Observer**
- GitHub Actions status, runner availability, exact source identity.

Observers generate events and evidence.

They must not independently rewrite strategies, deploy software or issue exchange orders.

## 9. Development Agent Workflow

When Codex detects a defect or missing scientific capability:

1. Obtain evidence.
2. Identify the owning repository.
3. Verify exact source SHA.
4. Create a reproducible failing test.
5. Prepare an isolated code change.
6. Run required tests.
7. Create a Draft PR.
8. Request independent review.
9. Publish evidence.
10. Submit a release candidate for separate admission.

No direct mutation of running production source.

No automatic main merge.

No deployment without authorized release gates.

## 10. Change Influence Model

Separate three authority levels.

### Level A — Observation

Read-only queries and diagnostic analysis.

No mutation.

### Level B — Research

Authorized creation of bounded research jobs, synthetic experiments and visualization artifacts.

No modification of production runtime or live market collectors.

### Level C — Operations

State-changing actions only through authenticated Control Plane, scoped approvals, fencing, release admission and Node Supervisor.

Require explicit operator authorization where policy demands it.

Never allow a natural-language prompt alone to bypass these checks.

Codex recommendations are not authority proofs.

## 11. Continuous Operation

Unified must continue collecting data and running admitted jobs when Codex is closed, disconnected or unavailable.

Persist research requests, jobs and results in existing durable systems.

Support reconnect and status reconciliation.

Do not require a permanent Codex Desktop session on every node.

Any proactive Codex execution must use a separately configured supported automation/agent mechanism, not an assumed permanently running chat session.
