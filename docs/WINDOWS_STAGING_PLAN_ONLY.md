# Windows staging PLAN_ONLY design

Goal: describe six initially intended Windows slots and future per-node changes without discovery, commands, installation or admission. The independent integration gate is open: source29ae8850bb3b75346857fe573844102c9919992a/tree7a4201a4a8329cba01e592ba6d63dbb714edf131, run41125641252 attempt1, four independently downloaded artifact ZIPs. That qualifies disposable source integration only. It does not close the dependency, sealed-handoff, physical or production gates.

Architecture: a pure build_staging_plan(source_lock, desired, previous=()) validates bounded declarative inputs, computes per-node membership/module/source differences and returns required evidence checks plus ordered review-operation enums. It has no host or file I/O, command/executor field, transport or credentials. An offline CI script reads repository fixtures, runs the suite and writes exact-checkout evidence. Six logical slot IDs are planning labels, never asserted host identities. Source pins identify code, never real installer artifacts/signers.

Approaches considered under the user's authorization to choose: extending legacy executable installers would create physical mutation paths and is excluded by PLAN_ONLY; expanding the old infrastructure package-lock v1 would conflate source declarations with authenticated application closure. Chosen: additive declarative model, leaving existing pure/security contracts unchanged. No existing limits are relaxed.

Boundaries: source lock has exactly five commit/tree pins. Desired roster <=64, each logical ID case-insensitively unique and <=64 ASCII characters, modules subset of the five known owners, intent PRESENT/DRAIN/RETIRE. Previous declarations bind the same identity to module list and source-lock digest. They are unverified input, not host facts. Limits match existing installer 64-node bound. Unknown keys, secrets, executable fields, authority overrides, unknown/duplicate modules, malformed identities/pins/digests, invalid type/bounds fail closed.

PRESENT unchanged yields KEEP with no staging operations; new/changed nodes yield ADD/UPDATE review proposals. UPDATE replacements require drain/lease/fencing review; module removal also requires revocation/retention review before closure review. DRAIN/RETIRE need a declared predecessor; removed previous nodes yield RETIRE proposals. No mutation or full-fleet reinstall is implied. At most128 union rows supports disjoint64-node desired/predecessor rosters. Each proposed destructive change requires drain, lease expiry/fencing/checkpoint review, backup/restore and separate physical approval before eventual decommission/revocation; no automated action exists.

Every inventory/dependency/security/capacity/backup/HA check is UNVERIFIED and physical probe NOT_RUN, including Windows10/11 build/architecture, PS5.1/7, Python>=3.11 application compatibility, exact Node22/24 selection, PG18 policy vs PG16/18 CI, SSH/Tailscale identities, service rights, ACL/firewall, PG schema roles, disk/headroom, failure domains, quorum/lease fencing, restore, RPO/RTO and release closure/SBOM/signers. Observed real measurements are not accepted by this version; future attested evidence requires a separate reviewed contract. Caller booleans cannot upgrade admission.

Application closure remains blocked: Math runtime imports pg although package places pg8.16.3 in devDependencies; npm omit-dev is not qualified. Strattester optional torch2.14.1/PyNaCl1.6.2/filelock extras and native CPU/CUDA/wheel compatibility unqualified; Grid broad requirements and optional ML extras unresolved. No fake version, package SHA or signer is supplied. See dependency audit for exact declarations/blob IDs. Strattester-to-Grid sealed receipt/dataset identity/completeness and release admission remain independent gates; no installer or CI PASS authorizes collection handoff/trades.

Validation: negative tests first, exact immutability, source/roster bounds, every injected secret/command/authority key, unknown facts, same-roster KEEP, add/drain/retire and source/module deltas, initial0/1/5/6/7/10/64 and65 rejection, no-I/O AST boundary, actual output qualification. Hosted Python3.11/3.13 Windows/Linux matrix records run/attempt/job/head/tree and downloads ZIP hashes. PS5.1/7 tests remain existing in-memory security checks; no package/probe is executed. Independent fresh review required before candidate evidence is reported.

## Gate and source audit record
The independently verified integration receipts are committed in windows-staging-integration-gate.json. The exact five current candidate pins are in windows-staging-sources.json. The earlier read-only dependency audit is retained as windows-staging-dependency-audit.json/.md and explicitly records its historical Unified29d61 audit HEAD; the current final Unified29ae was admitted only by the separate four-ZIP integration gate. The five source dependency declarations were rechecked unchanged between that audit and current final pins; these documents do not substitute old Grid/Strattester source revisions. Software gate verification never grants package, handoff, physical or production admission.

## Future physical approval gates (not performed)
Before any eventual physical inventory, owner approval must bind named node, allowed read-only probes, purpose and evidence destination. Before any installation/change, separate approval must bind exact authenticated artifact manifest, node identity and predecessor state, service/DB/schema/network rights, rollback/restore evidence and bounded scope. SSH/Tailscale enrollment and ACL/firewall/service/schema edits require their own explicitly approved deltas. HA admission additionally needs independently tested quorum/failure domains, durable fencing, leader/DB loss/restart/recovery, backup restore and actual RPO/RTO. Decommission must retain checkpoints/required data and revoke identities only after approved drain, lease expiry, fencing and retention checks. No operation here submits or executes those approvals.
