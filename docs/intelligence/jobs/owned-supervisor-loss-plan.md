## Existing mechanism and scope

Extended limits retain KILL_ON_JOB_CLOSE (0x2000). `_retire_owned` proves empty Job and process exit before closing retained handles on explicit abort. It cannot run Python cleanup after abrupt owner death. A parent must retain independent observation/custody; serialized local snapshots are not authority or adoptable handles.

The old qualify_windows_job script contains ResumeThread/load/memory modes and is NOT imported or executed. PR52 is not included or run. Reuse only primary Grid40e9 WindowsJob cleanup methods and the existing preparation API; no second authority, queue, ledger or publication.
